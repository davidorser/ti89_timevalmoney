Time value of money on a TI-89

Six engineering-economics time-value-of-money (TMV) functions, built from the equations and injected and tested on a working calculator, built in one conversation with Claude Code. This page describes how it went and includes the resulting files.

Get the functions

These files are embedded in this page, so the download links work even when the page is saved on its own. Send them to the calculator with TI Connect's Send To TI Device. They go to the main folder.

pf.89fP from F fp.89fF from P pa.89fP from A ap.89fA from P fa.89fF from A af.89fA from F txt2ti89.pyText → .89f converter

Run each function once after sending. The calculator stores them as text and converts them on their first run.

The six functions

Each one takes three arguments: an amount, i, the interest rate per period as a decimal, and n, the number of periods. Payments are at the end of each period. Results are plain amounts, with no positive/negative cash-flow signs.

FunctionFindsFormulaTest
pf(f,i,n)Present value of a future amountf/(1+i)^npf(1000,.06,5) → 747.258
fp(p,i,n)Future value of a present amountp·(1+i)^nfp(1000,.06,5) → 1338.23
pa(a,i,n)Present value of a series of paymentsa·(1−1/(1+i)^n)/ipa(100,.08,10) → 671.008
ap(p,i,n)Payment that pays off a present amountp·i/(1−1/(1+i)^n)ap(200000,.005,360) → 1199.10
fa(a,i,n)Future value of a series of paymentsa·((1+i)^n−1)/ifa(100,.05,10) → 1257.789
af(f,i,n)Payment that builds up to a future amountf·i/((1+i)^n−1)af(10000,.06/12,120) → 61.0205

When i = 0, the four payment functions skip the formula and use the simple answer instead: a·n, p/n, a·n and f/n.

Two things to watch. First, i and n must match the payment frequency: for monthly payments at 6% a year over 30 years, use .06/12 and 360. Second, for payments at the start of each period, multiply pa or fa by (1+i), or divide ap or af by (1+i).

The functions combine for problems that mix a lump sum and payments. For example, the present value of $200 a month for five years plus $5,000 at the end, at 6%:

pa(200,.005,60)+pf(5000,.005,60)

How it was built

The project took one session of back-and-forth with Claude Code. Each step below starts with the request that kicked it off.

  1. Write down the equations

    "Define and enumerate the time-value of money equations with an eye toward building TI-89 functions."

    Claude wrote a reference document, TVM_EQUATIONS.md. It starts from the single equation every TVM problem reduces to, in which all cash flows moved to the same date sum to zero:

    p·(1+i)^n + PMT·(1+i·k)·((1+i)^n − 1)/i + f = 0

    It then solves that equation for each variable and covers amortization, rate conversions, NPV and IRR. Every formula was checked numerically in Python, including the standard result that a $200,000, 30-year mortgage at 6% costs $1,199.10 a month.

  2. Use shorter names, and check END vs BEGIN

    "Change the variable names: p = present value, f = future value, i = interest rate as decimal, n = number of periods. Show me present value of a future worth with END and then BEGIN timing."

    The answer is the same either way: p = f/(1+i)^n. Payment timing only affects a stream of payments (the k term above), so it doesn't change a single lump sum.

  3. The first two functions: pf and fp

    "Let's start by creating two simplified TVM functions pf(f,i,n) and fp(p,i,n)."

    Each is a one-line TI-BASIC Func. The names follow the standard engineering-economics factors (P/F, F/P), which set the naming for the rest.

  4. Plan the payment pair, and look for gaps

    "Present Value of an annuity pa(a,i,n) and the Annuity of a present value ap(p,i,n). Let me know if you see any holes."

    The review turned up five issues:

    • No argument for payment timing.
    • Division by zero when i = 0.
    • The rate and period must match the payment frequency.
    • No support for a balloon payment.
    • Results have no cash-flow signs.

    The main decision was timing. The options were a fourth argument, separate BEGIN versions, or assuming END.

    Decision: assume END. This keeps every function at three arguments and matches the standard factor tables.

  5. Simpler code: If instead of when()

    "Remove the weird when() syntax and use a simple if() statement."

    The zero-rate case became a plain If i=0 / Return, which is easier to read on the calculator screen.

  6. TI Connect won't take .txt files

    "My TI-Connect software doesn't seem to accept .txt files. Can you export files compatible with Send To TI Device?"

    No ready-made tool for this turned up. The published TI-89 file guides cover the file header but not how a function is stored inside it. Claude filled the gap by comparing real .89f files saved from a calculator with their plain-text listings. They showed that functions are stored as plain text, not compiled code, so a converter only needs to wrap the text correctly. The format section has the details.

    The resulting converter, tools/txt2ti89.py, rebuilt one of the calculator-written samples byte for byte. All four functions then worked on the real calculator the first time.

  7. The last pair: fa and af

    "Plan the future-value annuity pair: fa(a,i,n) and af(f,i,n), END assumed."

    This pair followed the same pattern and raised no new issues. With the source written, the converter turned it into calculator files in one step. Both worked on the calculator.

  8. Knowing when to stop

    "At this point I'm good. No need for full solvers."

    The equation document also outlines full solvers with cash-flow signs, BEGIN timing, and solving for n and the rate. The six factors covered what was needed, so those stay as a plan only.

Inside a .89f file

A TI-89 variable file is a fixed 86-byte header followed by the variable's data and a checksum. Multi-byte header fields are stored low byte first, except the 2-byte variable size, which is stored high byte first.

OffsetBytesContents
0x008**TI89** signature
0x08201 00
0x0A8Folder name, zero padded (main)
0x1240Comment, zero padded
0x3A601 00 52 00 00 00
0x408Variable name, zero padded
0x484Type (13 = function, 12 = program), then 03 00 00
0x4C4Total file size, low byte first
0x502A5 5A
0x52400 00 00 00
0x562Variable size, high byte first
0x58nVariable data (below)
end2Checksum: low 16 bits of the sum of the size and data bytes

For a function that hasn't been run yet, the variable data is the source text with lines separated by carriage returns (0D), and without the function name or the leading colons. A fixed trailer follows:

"(a,i,n)" 0D "Func" 0D ... 0D "EndFunc"   source text
00                                        end of text
xx xx                                     editor cursor position
17 E4 E5 00 01 08 DC                      trailer for text-form functions

The comment symbol © is byte A9. The converter rejects any other non-ASCII character rather than guess its code.

Rebuild after editing a source file:

python3 tools/txt2ti89.py src/*.txt
